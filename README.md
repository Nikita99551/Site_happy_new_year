## Подключение бэкенда

Всё общение с сервером идёт через объект `api` (`src/shared/api/index.js`). Контракт описан в
`src/shared/api/types.js`, реализация на `fetch` — `src/shared/api/http.js`. Чтобы включить её, задайте
`VITE_API_MODE=http`. Сессия — cookie, запросы идут с `credentials: 'include'`.

| Метод `api` | Запрос | Ответ |
|---|---|---|
| `me()` | `GET /me` | `MeResponse` или 401 (гость) |
| `login(phone)` | `POST /auth/login { phone }` | `MeResponse` |
| `register({ fullName, phone, storeId, consents })` | `POST /auth/register`, `consents: { pd: true, rules: true, publish: boolean }` | `MeResponse` |
| `logout()` | `POST /auth/logout` | 204 |
| `registerReceipt(number, channel)` | `POST /receipts { number, channel: 'store' \| 'delivery' }` | `{ status: 'done', steps }` (`steps: 0`, если сумма меньше 600 ₽ — окно покажет, что шагов нет) или `{ status: 'processing' }` |
| `registerReceiptQr(qr)` | `POST /add_code_from_qr?qr=НОМЕР` (ЗАГЛУШКА, см. «Чек по QR-коду») | как у `registerReceipt`; 401 — не вошёл |
| `selectStore(storeId)` | `PATCH /me { storeId }` (гость: только локально) | 204 |
| справочники при старте | `GET /stores`, `GET /stats` | `Store[]`, `{ participants: number[] }` |

**Согласия при регистрации (03.11):** `pd` и `rules` обязательны, `publish` — по желанию (третья галочка «Если выиграю, разрешаю
опубликовать моё имя и фото с вручения приза»). Сохраните `publish` у участника: публиковать победителя можно только с `publish: true`.

После регистрации всегда открывается окно «Вы зарегистрированы» (`features/auth/ui/RegisteredModal.jsx`): оттуда — к окну чека
или на маршрут. После каждого чека показывается «Чек обрабатывается»: шаги начисляются сразу или чуть позже, человек увидит их
на «Моём маршруте» (окна «+N шагов» нет — правка 27.10). В окне чека две вкладки (правка 29.10, по фото настоящего чека «Аникс»):
- **«Покупка в магазине»** — поле «Код для регистрации с чека»: код под QR-кодом на чеке, латиница и цифры (тот же номер, что
  в ссылке QR, см. «Чек по QR-коду»). Поле само убирает пробелы и меняет похожие русские буквы на латинские (Н → H, У → Y…),
  отправляется строка `[0-9A-Za-z_-]`, от 4 знаков. Подсказка — нарисованный кусок чека (`ReceiptHint.jsx`), без данных покупателя.
- **«Заказ доставки»** — номер заказа из приложения «Торнадо» (только цифры). Подсказка «Где номер заказа» (`DeliveryHint.jsx`):
  три схематичных экрана приложения — профиль слева вверху → «История заказов» → номер в карточке, ссылка на приложение.

### Чек по QR-коду

На чеке печатается QR-код со ссылкой `https://promo.tdanix.ru/api/add_code_from_qr?qr=7Y8KYAIALAL507L2cd`,
где `qr` — номер чека (латиница и цифры). Код — `src/features/receipt-qr/`.

Что видит человек:
- **уже вошёл** — окно «Регистрируем чек», запрос уходит сразу, потом общее окно «Чек обрабатывается»;
- **гость** — «Войти или зарегистрироваться» с пояснением, что чек зарегистрируется сам. Сразу после входа
  или регистрации чек отправляется в фоне: после входа открывается окно этого чека, после регистрации итог виден
  плашкой в окне «Вы зарегистрированы»;
- гость закрыл окно — номер ждёт во вкладке (`sessionStorage`, ключ `anix_qr_pending`, сутки, переживает F5),
  чек зарегистрируется после любого входа (придёт уведомление «Чек с QR-кода принят…»);
- ошибка (чек уже зарегистрирован, лимит 5 чеков в день и т. п.) — окно с текстом `message` от сервера,
  кнопками «Попробовать ещё раз» и «Ввести номер вручную». 401 — сайт снова просит войти, номер не теряется.

Номер забирается из адреса до запуска роутера (`captureQrFromUrl` в `src/app/main.jsx`) и убирается из адреса:
«Назад» и F5 не отправят тот же чек второй раз. Сайт понимает и любую свою страницу с `?qr=НОМЕР` (`/?qr=…`, `/route?qr=…`).

**Что нужно сделать на сервере (на выбор, ЗАГЛУШКА — согласовать):**
1. Браузер открывает ссылку из QR обычным `GET` — на этот адрес нужно отдать сайт (`index.html`), а не JSON.
   Вариант А — хостинг: `GET /api/add_code_from_qr` с `Accept: text/html` → `index.html`.
   Вариант Б — бэкенд отвечает на этот `GET` редиректом `302 Location: /?qr=НОМЕР` (сайт поймёт `?qr=` сам).
2. Регистрация чека — `POST /api/add_code_from_qr?qr=НОМЕР` с cookie сессии, ответ как у `POST /receipts`:
   `{ status: 'processing' }` или `{ status: 'done', steps }`; ошибки — `{ message }` (409 «Этот чек уже зарегистрирован»,
   401 — не вошёл). Другой адрес — поменять одну строку в `src/shared/api/http.js` (`registerReceiptQr`).

Демо: `/api/add_code_from_qr?qr=7Y8KYAIALAL507L2cd` (на GitHub Pages —
https://nikita99551.github.io/Site_happy_new_year/api/add_code_from_qr?qr=7Y8KYAIALAL507L2cd) — чек «в обработке»,
через 2 минуты 2 шага; тот же номер второй раз — «Этот чек уже зарегистрирован»; битый номер — подсказка и окно ручного ввода.

Магазины (`GET /stores`): `id` — код магазина из базы, `name`, `address`, `district` — район или часть города (необязательно,
по нему тоже ищут), `max` — ссылка на чат MAX; пустая строка — чата нет или ссылку ещё проверяют, кнопка «Группа MAX» серая.
Демо-список (171 работающий магазин, 3 закрытых не показываются) — `src/shared/api/stores.data.js`. Поиск в окне выбора магазина — по началу слов названия, адреса
и района в любом порядке, «ё» = «е», «ул.», «с.» и т. п. можно не писать (`src/features/store-select/lib/search.js`).

Ошибки: любой статус кроме 2xx с телом `{ "message": "текст для пользователя" }` — сообщение показывается в форме.
Если тела с `message` нет (например, 500 со страницей ошибки), форма пишет «Что-то пошло не так, попробуйте ещё раз».
Нет интернета или сервер не ответил за 20 секунд — «Нет связи с сервером…» / «Сервер долго не отвечает…» (`http.js`, `TIMEOUT_MS`).
Форма `MeResponse` — в `types.js`: имя, телефон, магазин, `partnerStops` и **все чеки участника** (`receipts`).
Всё, что рисуется на «Моём маршруте», главной и в окнах, сайт строит из неё сам, дополнительных эндпоинтов не нужно.

Гость, нажавший «Зарегистрировать чек» или «Добавить чек», сначала видит окно входа; после входа или регистрации
сразу открывается окно чека (`NEEDS_AUTH` и `finishAuth` в `src/features/modal/ModalProvider.jsx`).

### Шаги считаются только из чеков (важно для базы данных)

История чеков, ёлка, гирлянда, «N из 30 шагов», «кругов пройдено» и «билетов» — это одно и то же число,
показанное по-разному. Чтобы они никогда не разошлись, источник у них один — таблица чеков:

- **В базе не хранить** отдельно «текущий шаг», «круг», «пройдено кругов», «билетов». Хранить только чеки:
  участник, номер, дата, статус (`processing` / `done`), сколько шагов дал чек (за сумму + за товары партнёров).
- `GET /me` отдаёт **все** чеки участника за акцию, включая чеки в обработке (это максимум 5 в день × 56 дней).
- Сайт сам считает (`src/shared/api/progress.js`, функция `toUser`):
  - всего шагов = сумма `steps` по чекам со статусом `done` (чеки в обработке шагов не дают);
  - пройдено кругов = всего шагов / 30 без остатка; **билетов = пройдено кругов**;
  - шаг в круге = остаток от деления на 30; ровно 30, 60, 90… = круг пройден, звезда горит, новый круг начнёт следующий чек;
  - чеков всего = длина списка.
- Для финала сервер считает билеты **той же формулой** из той же таблицы: `floor(SUM(steps WHERE status='done') / 30)`.
  Тогда число билетов на сайте и в розыгрыше совпадает. В **еженедельный** розыгрыш попадает каждый, у кого к концу недели
  есть хотя бы один шаг (`SUM(steps WHERE status='done') >= 1`, правка 03.11).
- Когда чек выходит из обработки, сервер меняет у него `status` на `done` и записывает `steps` — больше ничего;
  при следующем `GET /me` ёлка и история обновятся вместе.
- В истории сайт сам ставит отметку «Первый круг пройден — билет в финал» над чеком, который закрыл круг,
  и пишет итог «Зачислено 37 шагов за 12 чеков · 1 пройденный круг и 7 шагов во втором круге».

Пример (демо-участник 913 456‑78‑90): 12 чеков, 11 зачислены на 37 шагов, 1 в обработке →
второй круг, 7 шагов, 1 круг пройден, 1 билет.

Чек в `receipts` приходит с датой регистрации `at` (ISO 8601 с часовым поясом). Подпись «Только что»,
«5 минут назад», «Сегодня · 14:05», «Вчера · 09:31», «20 декабря · 18:42» сайт считает сам и обновляет раз в минуту.

### Демо-режим

`mock.js` отвечает сам и хранит состояние в `localStorage` (ключ `anix_demo`).
Сброс: открыть любую страницу с `?demo-reset` в адресе (например `/route?demo-reset`) — стираются демо-чеки, шаги, вход
и память анимации. После сброса «Регистрация» даёт нового участника с нуля (первый круг, 0 шагов),
«Войти» с номером 913 456‑78‑90 — пример участника (12 чеков на 37 шагов: второй круг, 7 шагов, 1 билет). У каждого номера в демо свой профиль:
можно выйти (меню под именем в шапке или «Выйти» в меню на телефоне) и войти другим номером. Вход по незарегистрированному номеру
и повторная регистрация того же номера дают понятную ошибку. На настоящем сервере `?demo-reset` ничего не делает.

Чек в демо: по последнему знаку номера — 1 → 2 шага, 2 → 3 шага, 0/3/6/9 → «в обработке» (через 2 минуты сам зачисляется
на 2 шага, видно после обновления страницы); если код с чека кончается буквой, шаги считаются так же по коду буквы.

### Ответы на задания партнёров (с 08.11)

(бесконечной ленты нет). Форма ответа — `AnswerFormModal.jsx`, крупный просмотр фото и видео — `entities/answer/ui/MediaViewer.jsx`.

| Метод `api` | Запрос | Ответ |
|---|---|---|
| `answers(slug, { sort, type, cursor, limit })` | `GET /partners/:slug/answers?sort=popular\|new&type=all\|text\|photo\|video&limit=20&cursor=…` | `AnswersPage` (`types.js`): `items`, `next` (курсор или `null`), `counts` (всего и по видам), `mine` (свой ответ в любом статусе или `null`) |

| `likeAnswer(id, like)` | `PUT /answers/:id/like` — поставить, `DELETE` — снять | `{ likes, liked }`; 401 — не вошёл |

Что проверяет сервер (сайт проверяет то же только для удобства):
- ОТВЕТЫ ВИДНЫ ТОЛЬКО ДОШЕДШИМ ДО ШАГА (правка 08.11, Никита): `GET /partners/:slug/answers` для гостя — 401, для участника,
  который ещё не дошёл до шага с коробкой этого партнёра, — 403. Сайт в этом случае показывает закрытую коробку с замком.
  Тексты заданий сейчас лежат в коде сайта (`PARTNER_TASKS`) и видны в его исходниках. Если задание нужно прятать и там,
  сервер отдаёт его отдельным запросом (например `GET /partners/:slug/task`, 403 до шага), а в коде остаются только шаг и партнёр;
- ответить может только вошедший участник, дошедший до шага с коробкой этого партнёра (`step >= шаг` в текущем круге
  или пройден хотя бы один круг) — как на ёлке; один ответ на задание (после отклонения можно прислать другой);
- что задание принимает: `accepts` у задания — `text`, `photo`, `video`, каждое `required` или `optional`; нет ни одного
  `required` — нужно хоть что-то одно. Текст до 1000 знаков. Фото JPEG, PNG, HEIC или WebP до 10 МБ; видео MP4 или MOV
  до 1 минуты и до 100 МБ (лимиты — `MEDIA_LIMITS` в `src/shared/lib/media.js`);
- ДО 3 ФОТО В ОТВЕТЕ (13.11, `MEDIA_LIMITS.photosMax`): поле `photo` приходит 1–3 раза, ответ отдаёт `photos: [{ src, w, h }]`
  по порядку (старое одиночное `photo` сайт тоже понимает). У задания бывает `minPhotos` — у «Простоквашино» и Зареченского 2
  (продукты и готовое блюдо / скриншоты двух отзывов); фото и видео вместе в одном ответе не бывает;
- `mustContain` — слова, без которых ответ не принимается (у «Алмака» «макароны Алмак»): без учёта регистра, «ё» = «е»;
  `textMax` — короткий ответ (вопрос Cola Bochkari — 100 знаков, слоган «Алмака» — 200);
- ВИКТОРИНА `hiddenAnswers` (Cola Bochkari, 4-й шаг): чужие ответы не отдавать никому — `GET /partners/bochkari/answers`
  возвращает `items: []`, нулевые `counts` и только свой `mine`. Правильного ответа в коде сайта нет и быть не должно (репозиторий
  открытый): его знают организатор и партнёр. Приз получают первые 20 правильных ответов — серверу хранить точное время ответа;
- `consent=1` — согласие показать ответ на сайте с именем и первой буквой фамилии. Галочки больше нет (09.11, решение Никиты):
  под кнопкой «Отправить ответ» приписка «Нажимая «Отправить ответ», вы соглашаетесь…», сайт шлёт `consent=1` с каждым ответом;
  сервер сохраняет факт и время согласия вместе с ответом (формулировку проверяют юристы);
- каждый ответ проверяет модератор: чужие ответы показываются только со `status: 'published'`, свой — автору в любом
  статусе (`review` — «на проверке», `rejected` — «не прошёл проверку»);
- подпись `author` («Анна К.») и `place` (город магазина) собирает сервер, полное ФИО и телефон не отдавать;
- нет ФИО (чек зарегистрирован на кассе, на сервере только телефон) — подписать ответ нечем. Для этого есть окно
  `features/update-fio` → `UpdateFIOModal` (09.11, пока никуда не подключено): одно поле ФИО, проверка «хотя бы фамилия и имя,
  только буквы», приписка-согласие на обработку ПДн под кнопкой. Сохранение — свойство `onSave(fio)`, пример подключения
  в комментарии в начале файла;
- фото уменьшить (до 1600 px) и убрать из него EXIF (там бывает геометка), видео перекодировать в MP4 H.264 и сделать
  кадр-обложку `poster`, длительность `duration` в секундах;
- сердечко — одно от участника на ответ, за свой ответ нельзя; порядок `popular` — больше сердечек выше, при равенстве новее.

В демо-режиме (`mock.js` + `shared/api/answers.demo.js`) у заданий готовые ответы-примеры, фото и видео-заглушки лежат
в `public/img/demo-answers/` (собраны из картинок сайта). Свой демо-ответ «на проверке» минуту, потом публикуется сам;
выбранное видео в демо играет только до перезагрузки страницы (файл в браузере не хранится). При подключении бэкенда
`answers.demo.js` и `public/img/demo-answers/` можно удалить.

## Анимация шагов и цифр (программистам ничего делать не нужно)

Все анимации прогресса уже готовы на фронтенде и работают от тех же полей `User`, что и остальной интерфейс.
От сервера нужно только одно: **`GET /me` всегда отдаёт актуальный полный список чеков**, а после `POST /receipts`
фронтенд сам перечитывает `GET /me`. Шаг, круг и билеты сайт считает из чеков (см. «Шаги считаются только из чеков»).

| Где | Что анимируется | Когда |
|---|---|---|
| «Мой маршрут», первый экран | гирлянда, большая цифра «N из 30», «до сертификата — N шагов», счётчики | сразу при открытии; если открыто окно — после его закрытия |
| «Мой маршрут», ёлка | шары зажигаются по одному, «Вы здесь» переезжает, звезда загорается на 30‑м шаге | когда ёлка появляется на экране |
| Главная, открытка «Ваш путь к подаркам» | гирлянда и цифра «N из 30» | когда открытка появляется на экране |

Как это устроено:
- Сайт сам запоминает в браузере, какой шаг человек видел в прошлый раз (`localStorage`, ключ `anix_route_seen`,
  отдельно для главной и «Маршрута», по номеру телефона). При следующем показе новые шаги «проходятся» по одному.
  В первый раз анимация идёт от старта текущего круга. Код: `src/entities/user/lib/stepAnimation.js`.
- Переход на новый круг: шаги доходят до 30, загорается звезда и летит конфетти, затем ёлка сбрасывается на старт
  нового круга, и шаги идут дальше. «Круг», «кругов пройдено» и «билетов» меняются в тот же момент.
- Если чек зарегистрирован, пока человек на «Маршруте», анимация ждёт закрытия окна и играет у него на глазах.
- Системная настройка «уменьшить движение» и `?noanim` в адресе: сразу показывается итоговое состояние.
- Новый участник (шаг 0): все шары прозрачные, «Вы здесь» не показывается.
- На телефоне (≤ 600 px) ёлка другая — вытянутая, 6 ярусов (`MOBILE_TREE` в `widgets/route-tree/geometry.js`),
  шары и цифры в 1,7 раза крупнее. Данные те же.

Остальное движение: параллакс при прокрутке только в первом экране главной (`shared/ui/parallax/useParallax.js`),
на курсор откликаются только гирлянды (`shared/ui/lights/useGarlandSway.js`), снег рисуется только на экране,
бесконечные анимации за экраном стоят на паузе (`shared/ui/reveal/usePauseOffscreen.js`).

## Загрузка, сборка и обновления (важно при выкладке)

- **Загрузочный экран.** Зелёный экран с логотипом и гирляндой, лампочки зажигаются по одной. Разметка и стили лежат в `index.html`
  (экран появляется раньше, чем загрузится код), та же разметка — `src/shared/ui/page-loader/PageLoader.jsx` (пока грузится страница).
  Показывается, только если загрузка дольше 0,25 с. После главной «Мой маршрут» подгружается в фоне (`usePrefetchPages`
  в `src/app/router/index.js`), поэтому переход мгновенный даже на 3G.
- **Порядок стилей в сборке.** Vite 8 ставит стили общих кусков кода (шапка, подвал) раньше стилей точки входа, где лежит база
  (`.btn` и т. п.), и база перебивала уточнения компонентов — на телефоне в шапке вылезала кнопка «Зарегистрировать чек».
  Плагин `globalCssFirst` в `vite.config.js` ставит стили точки входа первыми. Не удалять. Проверка: в `dist/index.html`
  первой ссылкой `stylesheet` идёт `index-*.css`.
- **Выкладка новой версии.** У человека с открытой вкладкой старые файлы страниц пропадают (404). Сайт в этом случае один раз
  сам перезагружается и подтягивает новую версию (`withReload` в роутере); если не помогло — экран «Что-то пошло не так»
  с кнопкой «Обновить страницу» (`src/app/ErrorBoundary.jsx`). На хостинге: `index.html` отдавать без кэша
  (`Cache-Control: no-cache`), файлы `/assets/*` — с долгим кэшем (в имени есть хэш), старые `/assets` после выкладки
  желательно держать ещё сутки.
- **Узкие телефоны (< 360 px в портрете,** старые iPhone SE, Android с крупным масштабом интерфейса): `main.jsx` просит браузер
  показать страницу шириной 360 и уменьшить под экран — вёрстка рассчитана от 360 px.
- **Окна.** Переход на другую страницу (в том числе «Назад» в браузере) закрывает открытое окно.
  Крестик и Esc в окнах входа, регистрации и выбора магазина возвращают в окно, из которого пришли
  (история окон — `features/modal/ModalProvider.jsx`, метод `back`); в первом окне крестик закрывает всё.

## Безопасность

- Внешних подключений нет: шрифты, картинки и скрипты свои. Инлайн-скриптов нет, персональные данные выводятся
  как текст (React экранирует), единственный `dangerouslySetInnerHTML` — статичные SVG-пути плашек (`shared/ui/svg-shapes`).
- Согласия на правила и обработку ПДн — отдельные чекбоксы, не отмечены заранее; cookie-баннер, счётчики подключать
  только после согласия (`widgets/cookie-banner`).
- Проверки в формах — только для удобства. Настоящая валидация, лимиты (5 чеков в день, один чек один раз, частота
  запросов), защита от перебора номеров — на сервере.
- На хостинге задать заголовки: `Content-Security-Policy` (`default-src 'self'; img-src 'self' data:; style-src 'self'
  'unsafe-inline'; script-src 'self'; font-src 'self'; connect-src 'self'; frame-ancestors 'self'; object-src 'none'`),
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS. Для SPA-роутинга
  все пути отдавать на `index.html` (кроме `/api/*`; для `GET /api/add_code_from_qr` — см. «Чек по QR-коду»).
